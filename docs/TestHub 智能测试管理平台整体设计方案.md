# TestHub 智能测试管理平台整体设计方案

## 文档概述

本文档为 TestHub 智能测试管理平台提供完整的技术架构设计方案。TestHub 是一个融合 AI 能力的测试管理平台，涵盖手工测试、API 自动化测试、Web UI 自动化测试和 APP 自动化测试四大测试领域，并通过 AI 技术实现需求文档解析、测试用例自动生成和智能浏览器操作等功能。

------

### 1.1 用户层

用户层是整个系统的入口，面向以下四类核心用户群体：

| 用户角色         | 职责与权限                                 | 典型操作                         |
| :--------------- | :----------------------------------------- | :------------------------------- |
| 测试经理         | 制定测试策略、管理测试资源、查看质量报告   | 创建项目、分配评审、查看统计报告 |
| 手工测试工程师   | 编写和管理测试用例、参与评审、执行测试计划 | 用例编写、计划执行、缺陷记录     |
| 自动化测试工程师 | 开发 API 脚本、UI/APP 自动化用例、维护框架 | 脚本开发、定时任务配置、报告分析 |
| 开发工程师       | 参与用例评审、查看测试报告、修复缺陷       | 查看测试计划、评审用例、查看报告 |

### 1.3 业务逻辑层

业务逻辑层是整个系统的核心，包含八大功能模块：

#### 模块一：用户认证与项目管理

*# users 模块职责*

\- 用户注册登录（JWT Token 双令牌机制）

\- 用户资料管理（头像、手机、部门、职位）

\- 用户配置管理（主题、语言、通知设置）

*# projects 模块职责*

\- 项目 CRUD 操作

\- 项目成员管理（Owner/Admin/Developer/Tester/Viewer 五级角色）

\- 项目环境变量配置（多环境支持）

\- 版本/发布管理

核心业务流程：

用户登录 → JWT Token 发放 → 访问项目列表 → 选择项目 → 进入对应测试模块

​                                            ↓

​                        创建/编辑项目 → 添加成员 → 配置环境 → 开始测试工作

#### 模块二：手工测试管理

*# testcases 模块职责*

\- 测试用例 CRUD（标题、前置条件、步骤、预期结果）

\- 用例附件上传和管理

\- 用例评论和讨论

\- 用例标签管理

\- 用例与版本关联

*# executions 模块职责*

\- 测试计划创建和管理

\- 测试执行（TestRun）生命周期管理

\- 用例执行状态跟踪（Untested/Pass/Fail/Blocked/Retest）

\- 执行进度实时统计

\- 执行历史记录

*# reviews 模块职责*

\- 测试用例评审工作流

\- 评审模板管理（检查清单）

\- 评审分配和状态跟踪

\- 评审意见（三级：整体/用例/步骤）

核心业务流程：

上传需求文档 → AI 解析生成用例 → 评审用例 → 采纳用例

→ 创建测试计划 → 分配执行 → 执行用例记录结果 → 跟踪进度 → 生成报告

#### 模块三：API 接口测试

*# api_testing 模块职责*

\- API 项目管理（HTTP/WebSocket 双类型）

\- 集合树形管理（父子层级）

\- API 请求完整配置

  \- 请求方法、URL、Headers、Params

  \- Body 类型（None/JSON/FormData/Raw）

  \- 认证配置（None/Basic/Bearer/API Key）

  \- 前置/后置脚本

  \- 断言配置（StatusCode/JSONPath/Header/Body/ResponseTime）

\- 环境变量管理

\- 测试套件编排

\- 执行结果和统计

\- 请求历史记录

\- 定时任务调度

核心业务流程：

创建项目 → 创建集合 → 添加 API 请求 → 配置环境和断言

→ 创建测试套件 → 编排执行顺序 → 单次/定时执行 → 查看报告

#### 模块四：UI 自动化测试

*# ui_automation 模块职责*

\- UI 项目管理（Playwright/Selenium 双引擎）

\- 定位策略管理（CSS/XPath/ID/Name 等 9 种策略）

\- 元素管理

  \- 主定位器 + 备用定位器（多级兜底）

  \- 元素分组树形管理

  \- 定位器有效性验证

\- 页面对象模式

  \- POM 代码生成

  \- 支持 JavaScript/Python 语言

\- 测试脚本管理

  \- CODE/LOW_CODE/NO_CODE 三种类型

  \- 脚本步骤编排

\- 测试套件编排

\- 执行记录和截图

\- Allure 报告生成

\- 定时任务调度

核心业务流程：

创建项目 → 捕获/添加元素 → 创建页面对象 → 编写测试脚本

→ 添加到测试套件 → 手动/定时执行 → 查看报告

#### 模块五：UI 自动化 AI 智能模式

*# AI 智能模式职责*

\- 自然语言任务描述

\- AI 意图理解和任务拆解

\- Browser Use 集成（LangChain）

\- 浏览器操作录制

\- 操作日志流式输出

\- GIF 动画生成

\- 自动保存为测试用例

核心业务流程：

输入任务描述（如：打开百度，搜索"TestHub"）→ AI 解析意图

→ Browser Use 执行浏览器操作 → 流式输出操作日志

→ 生成 GIF 动画 → 可选保存为测试用例

#### 模块六：APP 自动化测试

*# app_automation 模块职责*

\- APP 项目管理

\- 设备管理

  \- ADB 本地设备发现

  \- 远程设备连接

  \- 设备截图

  \- 设备锁定/释放（防止并发冲突）

\- 应用包名管理

\- 元素管理（图片/坐标/区域 三种类型）

\- 组件系统

  \- 基础组件（预定义动作）

  \- 自定义组件（JSON 定义）

  \- 组件包导入/导出

\- 用例编排（JSON Flow 定义）

\- 测试套件编排

\- 执行记录和截图

\- 定时任务调度

核心业务流程：

连接设备 → 发现/添加设备 → 锁定设备 → 创建项目

→ 捕获元素 → 编排用例流程 → 添加到套件 → 执行测试 → 释放设备

#### 模块七：AI 需求分析与用例生成

*# requirement_analysis 模块职责*

\- 需求文档上传和处理

  \- 支持 PDF/Word/TXT/Markdown

  \- 文档解析和文本提取

\- 业务需求提取（AI 分析）

\- 测试用例自动生成（AI）

  \- 支持流式输出和批量输出

  \- Writer 角色生成用例

  \- Reviewer 角色评审用例

  \- 根据评审反馈改进用例

\- AI 模型配置管理

  \- DeepSeek/Qwen/硅基流动/智谱

  \- 多角色配置（Writer/Reviewer/Browser Use）

\- 提示词模板管理

\- 生成策略配置

AI 服务集成架构：

用户上传文档 → 系统解析文本 → 切分文本块 → 分块发送给 AI

​              ┌───────────────────────────────┼───────────────────────────────┐

​              ↓                               ↓                               ↓

​        DeepSeek API                    通义千问 API                    硅基流动 API

​              ↓                               ↓                               ↓

​        响应流式返回 ◄────────────────────────┘                               │

​              ↓                                                                 │

​        用例组装 → 存储到数据库 → 流式输出给前端                                   │

​              ↓                                                                 │

​        AI 评审 → 反馈改进 → 采纳/弃用                                          │

​              ↓                                                                 │

​        最终用例保存 → 可关联到项目                                             │

#### 模块八：辅助功能模块

*# assistant 模块职责*

\- Dify AI 助手集成

\- 会话管理（多会话支持）

\- 消息历史记录

\- WebSocket 流式通信

*# data_factory 模块职责*

\- 测试数据生成

  \- 个人数据（姓名、手机、邮箱、身份证、银行卡）

  \- 企业数据（公司名、统一社会信用代码）

\- JSON 工具（格式化/验证/转换/比对）

\- 编码工具（Base64/JWT/URL/Timestamp）

\- 随机工具（整数/浮点/字符串/UUID/IP/MAC）

\- 加密工具（MD5/SHA/AES）

\- Crontab 工具（表达式生成/解析/验证）

*# reports 模块职责*

\- 概览数据（活跃计划、进度、通过率）

\- 状态分布统计（饼图）

\- 缺陷分布分析（按优先级）

\- 失败用例 TOP 排行

\- 执行趋势分析（折线图）

\- AI 效能分析（生成数/采纳率/覆盖率）

\- 团队工作量统计

*# core 模块职责*

\- 统一通知配置管理

\- Webhook 机器人配置

  \- 飞书机器人

  \- 企业微信机器人

  \- 钉钉机器人

\- 邮件通知配置

JWT 认证机制实现：

*# 认证流程*

1. 用户登录 → POST /api/users/login/
2. 后端验证密码 → 生成 access_token + refresh_token
3. 前端存储 Token → localStorage
4. 后续请求 → Header: Authorization: Bearer <access_token>
5. Token 过期 → 前端自动调用 /api/users/token/refresh/
6. 获取新 Token → 继续请求

class IsProjectMember(BasePermission):

​    """

​    检查用户是否为项目成员

​    """

​    def has_permission(self, request, view):

​        project_id = view.kwargs.get('project_id') or request.data.get('project')

​        if not project_id:

​            return True  *# 列表页等不需要项目权限*

​        

​        return ProjectMember.objects.filter(

​            project_id=project_id,

​            user=request.user

​        ).exists()

class ProjectObjectPermission(BasePermission):

​    """

​    对象级权限，根据角色判断操作权限

​    """

​    def has_object_permission(self, request, view, obj):

​        project = obj.project if hasattr(obj, 'project') else obj

​        

​        membership = ProjectMember.objects.filter(

​            project=project,

​            user=request.user

​        ).first()

​        

​        if not membership:

​            return False

​        

​        *# Owner 和 Admin 可以做任何操作*

​        if membership.role in ['owner', 'admin']:

​            return True

​        

​        *# Viewer 只能读*

​        if membership.role == 'viewer' and request.method in SAFE_METHODS:

​            return True

​        

​        *# Developer 可以读写执行相关*

​        if membership.role == 'developer':

​            return request.method in SAFE_METHODS + ['POST']

​        

​        *# Tester 可以执行和提交*

​        if membership.role == 'tester':

​            return request.method in SAFE_METHODS + ['POST', 'PATCH']

​        

​        return False

class AIModelService:

​    MAX_RETRIES = 3

​    RETRY_DELAYS = [1, 3, 10]  *# 秒*

​    

​    def call_with_fallback(self, user_message, config_list):

​        """

​        尝试多个 AI 服务提供商，自动降级

​        """

​        for config in config_list:

​            for i in range(self.MAX_RETRIES):

​                try:

​                    response = self.call_api(config, user_message)

​                    return response

​                except Exception as e:

​                    logger.warning(f"Provider {config.provider} failed: {e}")

​                    if i < self.MAX_RETRIES - 1:

​                        time.sleep(self.RETRY_DELAYS[i])

​        

​        raise AIProviderError("所有 AI 服务提供商均不可用")

​    

​    def call_stream_with_fallback(self, user_message, config_list):

​        """

​        流式调用，支持降级

​        """

​        for config in config_list:

​            try:

​                return self.call_stream_api(config, user_message)

​            except Exception as e:

​                logger.warning(f"Stream provider {config.provider} failed: {e}")

​                continue

​        

​        raise AIProviderError("所有流式服务均不可用")

## 八、总结

### 8.1 项目优势

1. 全链路测试覆盖：从手工测试到 API/UI/APP 自动化，一站式管理
2. AI 深度集成：需求分析、用例生成、智能评审全流程 AI 赋能
3. 现代化技术栈：Django 4.2 + Vue 3 + Vite，技术先进
4. 企业级架构：完善的权限控制、定时任务、通知体系
5. 模块化设计：15 个独立应用模块，高内聚低耦合

### 8.2 未来规划

1. AI 增强：更多 AI 能力的集成，如智能缺陷分析、测试用例优化建议
2. 云原生：容器化部署、K8s 编排支持
3. 多租户：支持 SaaS 化部署
4. 生态集成：GitLab/Jenkins/飞书/钉钉深度集成
5. 移动端：APP 原生支持
