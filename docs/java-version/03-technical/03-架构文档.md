## 一、项目概述

### 1.1 项目背景

TestHub 是一款 AI 驱动的测试管理平台，Python 版本（Django + Vue 3）已稳定运行。现计划使用 Java (Spring Boot) 重写后端，以获得更好的性能、企业级支持和技术生态。

### 1.2 项目目标

- 保持与 Python 版本功能完全一致
- 提升系统性能和并发处理能力
- 提供更好的企业级特性（微服务支持、更好的可维护性）
- 前端保持 Vue 3 不变，实现前后端解耦

### 1.3 项目范围

**包含**：
- 15 个核心业务模块
- 88 张数据库表
- REST API 接口
- JWT 双 Token 认证
- AI 集成（需求分析、测试用例生成）

**不包含**：
- 前端代码（Vue 3 保持现有版本）
- Python 版本维护


### 5.2 响应格式

```json
// 成功响应
{
  "code": 200,
  "message": "success",
  "data": { ... },
  "timestamp": 1713000000000
}

// 分页响应
{
  "code": 200,
  "message": "success",
  "data": {
    "records": [...],
    "total": 100,
    "current": 1,
    "size": 20
  },
  "timestamp": 1713000000000
}

// 错误响应
{
  "code": 1001,
  "message": "用户名或密码错误",
  "timestamp": 1713000000000
}
```

### 5.3 响应码规范

| 范围 | 含义 |
|------|------|
| 200 | 成功 |
| 400 | 请求参数错误 |
| 401 | 未认证 / Token 无效 |
| 403 | 无权限 |
| 404 | 资源不存在 |

| 1100-1199 | 权限相关错误 |
| 2000-2999 | 业务相关错误 |

## 六、安全设计

### 6.1 认证机制

**双 Token 机制**：

| Token | 有效期 | 存储位置 | 用途 |
|-------|--------|----------|------|
| Access Token | 15 分钟 | 内存/LocalStorage | API 访问认证 |
| Refresh Token | 7 天 | 数据库 + Redis 黑名单 | 刷新 Access Token |

**认证流程**：

1. 用户登录 → 返回 Access Token + Refresh Token
2. 每次请求携带 Access Token
3. Access Token 过期 → 调用刷新接口
4. Refresh Token 过期 → 重新登录
5. 退出登录 → Refresh Token 加入黑名单

### 6.2 项目级权限

| 角色 | 代码 | 权限范围 |
|------|------|----------|
| 负责人 | owner | 全部权限 |
| 管理员 | admin | 大部分权限 |
| 开发者 | developer | 用例编写、执行 |
| 测试者 | tester | 用例执行、查看 |
| 观察者 | viewer | 仅查看 |
