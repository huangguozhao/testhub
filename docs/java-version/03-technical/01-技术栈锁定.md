## 三、核心技术栈详解

### 3.1 基础框架

| 技术 | 版本 | 用途 | 选型理由 |
|------|------|------|----------|
| **Java** | 17 LTS | 编程语言 | 稳定 LTS 版本，系统已安装 Eclipse Temurin 17.0.17，Spring Boot 3.x 要求 Java 17+，社区资料丰富 |
| **Spring Boot** | 3.2.x LTS | Web 框架 | 企业级标准，LTS 稳定版，生态完善，文档齐全，AI 辅助开发出错率低 |
| **Spring Security** | 6.x | 认证授权 | 与 Spring Boot 深度集成，JWT 支持成熟 |

**为什么选择 Java 17 而不是 21？**

- 系统已安装 JDK 17 (Eclipse Temurin 17.0.17)，无需额外安装
- Java 17 是 Spring Boot 3.x 的最低要求，完全兼容
- Java 21 的虚拟线程（Virtual Threads）等新特性对当前项目非必需
- 后续如需升级到 Java 21，代码层面无需修改

### 3.2 ORM 框架

| 技术 | 版本 | 用途 | 选型理由 |
|------|------|------|----------|
| **MyBatis-Plus** | 3.5.x | ORM 框架 | - 国产开源，文档中文友好<br>- 内置 CRUD、分页、代码生成<br>- SQL 可控，利于性能调优<br>- Vuebill 团队维护，社区活跃 |
| **MySQL** | 8.0+ | 数据库 | - 与 Python 版本保持一致<br>- utf8mb4 字符集支持 emoji<br>- 8.0 窗口函数、性能提升 |

**MyBatis-Plus vs JPA/Hibernate 对比**

| 对比项 | MyBatis-Plus | JPA/Hibernate |
|--------|--------------|---------------|
| SQL 控制 | 手写/自动生成，可优化 | 自动生成，黑盒风险 |
| 学习曲线 | 中等，需熟悉 SQL | 较高，概念多 |
| CRUD 效率 | 自动生成，简单场景快 | 快速，但复杂查询需 JPQL |
| 社区资源 | 国内丰富 | 国际丰富 |
| **适合场景** | **业务复杂、性能敏感** | **快速原型、简单 CRUD** |

**结论**：TestHub 业务复杂（88 张表），MyBatis-Plus 更适合。

### 3.3 认证授权

| 技术 | 版本 | 用途 | 选型理由 |
|------|------|------|----------|
| **JWT** | JJWT 0.12+ | Token 认证 | - 无状态认证，适合分布式<br>- Access Token + Refresh Token 双 Token 机制<br>- 与 Spring Security 集成成熟 |
| **Redis** | 7.x | Token 存储 | - Refresh Token 黑名单存储<br>- Session 缓存<br>- 分布式环境下 Token 失效更及时 |

**为什么不只用 JWT？**

- JWT 优点：服务端无状态，扩展性好
- JWT 缺点：Token 泄露后难以立即失效
- **解决方案**：Refresh Token 存 Redis，Access Token 短期有效（如 15 分钟），Refresh Token 长期有效（如 7 天）
- 退出登录时将 Refresh Token 加入黑名单

### 3.4 任务调度

| 技术 | 版本 | 用途 | 选型理由 |
|------|------|------|----------|
| **XXL-JOB** | 2.4+ | 分布式任务调度 | - 国产开源，美观管理界面<br>- 任务管理、调度日志、告警完善<br>- 与 Spring Boot 集成简单<br>- 支持任务分片、失败重试、任务依赖 |
| **Quartz** | 2.3+ | 单机任务调度 | - Spring 内置支持<br>- 适合简单定时任务<br>- 分布式支持弱 |

**Python 版本用的是 Celery，为什么换成 XXL-JOB？**

| 对比项 | Celery (Python) | XXL-JOB (Java) |
|--------|-----------------|----------------|
| 生态 | Python 专属 | Java 专属 |
| 管理界面 | Flower (简陋) | XXL-JOB admin (美观) |
| 任务依赖 | Celery Chain | XXL-JOB 任务依赖 |
| 失败重试 | 支持 | 支持 |
| 调度方式 | Beat 轮询 / Broker 消息 | RPC 调用 |

**结论**：XXL-JOB 功能更全面，界面更友好，适合企业级使用。

**为什么不选 PowerJob？**

- PowerJob 也优秀，但 XXL-JOB：
  - 发布更早，社区更大
  - 文档更完善
  - 问题解决方案更多

### 3.5 文件存储

| 技术 | 版本 | 用途 | 选型理由 |
|------|------|------|----------|
| **MinIO** | Latest | 对象存储 | - S3 协议兼容<br>- 私有化部署友好<br>- 支持分布式<br>- 单机部署简单 |
| **AWS S3** | - | 云存储（可选） | - 生产环境可选<br>- 与 MinIO API 兼容 |

**为什么不直接用本地存储？**

- Python 版本用本地存储 + Django FileField
- Java 版本建议：
  - **开发/测试环境**：本地存储
  - **生产环境**：MinIO 或 S3
- Spring Boot 通过 `application.yml` 配置多存储后端

**存储策略建议**

```yaml
# application.yml
spring:
  servlet:
    multipart:
      max-file-size: 100MB
      max-request-size: 100MB

  storage:
    type: local  # local / minio / s3
    local:
      path: /data/testhub/uploads
    minio:
      endpoint: http://localhost:9000
      access-key: minioadmin
      secret-key: minioadmin
      bucket: testhub
```

### 3.6 缓存

| 技术 | 版本 | 用途 | 选型理由 |
|------|------|------|----------|
| **Redis** | 7.x | 缓存、会话、消息队列 | - 用途多样（缓存 + 消息）<br>- 与 XXL-JOB Spring Boot Starter 集成简单<br>- Lettuce 客户端性能好 |
| **Spring Data Redis** | 3.x | Java Redis 客户端 | - 官方推荐<br>- 模板化操作简单 |

## 四、功能模块技术选型

### 4.1 API 测试模块

| 技术 | 用途 | 选型理由 |
|------|------|----------|
| **HttpClient** | HTTP 请求 | Spring 内置，性能好 |
| **OkHttp** | WebSocket 连接 | WebSocket 支持更好 |
| **Selenium** | UI 自动化 | 成熟稳定 |
| **Playwright** | 现代浏览器自动化 | 微软出品，跨浏览器支持好 |

**为什么不选 RestTemplate？**

- RestTemplate 已进入维护模式
- Spring 官方推荐 **WebClient** (同步/异步) 或 **RestClient** (Spring 6.1+)
- 建议使用 **RestClient**（Spring 6.1 新特性，API 更简洁）

### 4.2 UI 自动化模块

| 技术 | 用途 | 选型理由 |
|------|------|----------|
| **Selenium** | Web 自动化 | 成熟稳定，生态完善 |
| **Playwright** | 现代浏览器 | 微软出品，无头浏览器支持好 |
| **Appium** | APP 自动化 | 跨平台移动端测试标准 |

**Java 版本的 UI 自动化**

- Selenium：使用 selenium-java (WebDriver)
- Playwright：使用 playwright (微软官方 Java binding)
- Appium：使用 java-client

### 4.3 AI 集成

| 技术 | 用途 | 选型理由 |
|------|------|----------|
| **LangChain4j** | AI 框架 | Java 版 LangChain，文档完善 |
| **DeepSeek SDK** | DeepSeek API | 官方 Java SDK |
| **阿里云百炼 SDK** | Qwen API | 阿里云官方 SDK |

**为什么不直接用 HTTP 调用？**

- LangChain4j 提供：
  - 统一抽象层（换模型只需改配置）
  - 提示词模板管理
  - 对话历史管理
  - 工具调用支持
- SDK 相比 HTTP 调用：
  - 类型安全
  - 重试、熔断封装
  - 模型特定优化

### 8.4 AI 框架说明

| 国际 | OpenAI、Anthropic、Google Gemini | LangChain4j 内置 |

**初始阶段建议**：
- 先接入 DeepSeek API（成本低、效果好）
- LangChain4j 配置简单，适合快速验证

### 8.5 CI/CD 说明

| 工具 | 说明 |
|------|------|
| **Jenkins** | 老牌 CI/CD 工具，插件丰富，社区成熟 |
| GitHub Actions | 与 GitHub 深度集成，YAML 配置 |
| GitLab CI | 与 GitLab 深度集成 |

**推荐理由**：
- Jenkins 插件生态最成熟（ thousands of plugins）
- TestHub 是企业级产品，Jenkins 部署/运维资料最丰富
- 支持分布式构建，适合团队协作
- 页面可视化，配置直观

**Jenkinsfile 示例结构**：

```groovy
pipeline {
    agent any
    
    stages {
        stage('Checkout') {
            steps {
                git branch: 'main', url: 'https://github.com/your-org/testhub-java.git'
            }
        }
        stage('Build') {
            steps {
                sh 'mvn clean package -DskipTests'
            }
        }
        stage('Test') {
            steps {
                sh 'mvn test'
            }
        }
        stage('SonarQube') {
            steps {
                withSonarQubeEnv('SonarQube') {
                    sh 'mvn sonar:sonar'
                }
            }
        }
        stage('Deploy') {
            steps {
                script {
                    if (env.BRANCH_NAME == 'main') {
                        sh 'kubectl apply -f k8s/'
                    }
                }
            }
        }
    }
}
```

## 十、Docker 部署指南

### 10.1 概述

项目依赖的中间件服务（Redis、MinIO、XXL-JOB）通过 Docker Compose 部署，简化环境搭建。

### 10.2 前置条件

- Docker Desktop 已安装并启动
- Docker Compose 已启用（Docker Desktop 自带）

### 10.3 快速启动

```bash
# 1. 进入项目根目录
cd D:\Project\testhub_platform

# 2. 复制环境变量配置（可选，有默认值）
cp docker/.env.docker.example .env.docker

# 3. 启动所有服务
docker-compose up -d

# 4. 查看服务状态
docker-compose ps

# 5. 查看日志
docker-compose logs -f [服务名]
```

### 10.4 服务访问地址

| 服务 | 地址 | 账号/密码 | 说明 |
|------|------|-----------|------|
| Redis | localhost:6379 | - | 密码: testhub123 |
| MinIO API | localhost:9000 | minioadmin/minioadmin | S3 兼容 API |
| MinIO Console | localhost:9001 | minioadmin/minioadmin | Web 管理界面 |
| XXL-JOB Admin | localhost:8080 | admin/123456 | 任务调度管理 |

### 10.5 环境变量配置

创建 `.env.docker` 文件自定义配置：

```bash
# Redis
REDIS_PASSWORD=testhub123
REDIS_PORT=6379

# MinIO
MINIO_ROOT_USER=minioadmin
MINIO_ROOT_PASSWORD=minioadmin
MINIO_API_PORT=9000
MINIO_CONSOLE_PORT=9001

# XXL-JOB
XXL_JOB_ADMIN_PORT=8080
XXL_JOB_MYSQL_PORT=3307
XXL_JOB_MYSQL_ROOT_PASSWORD=root
XXL_JOB_MYSQL_DATABASE=xxl_job
```

### 10.6 常用命令

```bash
# 启动服务
docker-compose up -d

# 停止服务
docker-compose down

# 停止并删除数据卷
docker-compose down -v

# 重启服务
docker-compose restart [服务名]

# 查看日志
docker-compose logs -f [服务名]

# 进入容器
docker exec -it testhub-redis sh
docker exec -it testhub-minio sh
```
